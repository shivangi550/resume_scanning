# ResumeIQ – Intelligent Resume Screening System

An automated resume screening system built with Python and Streamlit that extracts information from resumes, compares candidates with a Job Description (JD), calculates candidate scores, ranks candidates, and provides an explainable screening summary.

---

##  Project Overview

Recruiters often have to manually review a large number of resumes for a single job opening.

This project automates the initial resume screening process by:

- Extracting text from PDF resumes
- Cleaning and preprocessing resume text
- Extracting candidate information
- Extracting requirements from a Job Description
- Matching candidate skills with required skills
- Comparing candidate experience with required experience
- Comparing candidate education with job requirements
- Comparing resumes using TF-IDF similarity
- Comparing resumes using Word2Vec similarity
- Comparing resumes using SBERT semantic similarity
- Calculating a final candidate score
- Ranking candidates
- Explaining why a candidate received a particular score
- Displaying screening analytics
- Exporting results to Excel/CSV

The application provides an interactive Streamlit dashboard for recruiters.

## 6. Candidate Scoring

Candidates receive a final score based on multiple factors.

Current scoring formula:
```text
Final Score =
    30% × TF-IDF Similarity
  + 50% × Skill Match
  + 15% × Experience Match
  + 5% × Education Match
```
The final score is represented as a percentage from 0–100.

Note: These weights are project-defined prototype weights and are not intended to represent a validated hiring standard

### Note on NLP Models

Currently, the final candidate ranking is calculated using TF-IDF similarity, skill matching, experience matching, and education matching.

Word2Vec and SBERT are included for NLP model comparison and research purposes. Their scores are displayed separately and do not currently affect the final ranking score.


## 7. NLP Model Comparison

ResumeIQ uses multiple Natural Language Processing approaches to analyze the similarity between a candidate's resume and the job description.

The system compares three NLP techniques:

- TF-IDF
- Word2Vec
- SBERT

### TF-IDF

TF-IDF (Term Frequency–Inverse Document Frequency) measures similarity based on the importance of words shared between the resume and job description.

Advantages:
- Fast and lightweight
- Easy to interpret
- Effective for keyword-based matching

Limitations:
- Does not understand semantic meaning
- Treats similar words as different terms

### Word2Vec

Word2Vec converts words into numerical vector representations and compares semantic relationships between words.

Advantages:
- Captures relationships between words
- Provides vector-based text representation
- Can detect some semantic similarity

Limitations:
- Performance depends on the training corpus
- Does not fully understand sentence context

### SBERT

SBERT (Sentence-BERT) uses transformer-based embeddings to compare the semantic meaning of the complete job description and resume.

Advantages:
- Strong semantic understanding
- Captures contextual relationships
- More effective for meaning-based similarity

Limitations:
- Computationally more expensive than TF-IDF
- Requires downloading and loading a transformer model

### Model Comparison

The application displays a comparison table and visualization showing the similarity scores generated by:

- TF-IDF
- Word2Vec
- SBERT

This allows users to observe how different NLP techniques evaluate the same candidate.

## 8. Candidate Ranking

Candidates are automatically sorted according to their final score.

Example:
```text
Rank    Candidate        Score
--------------------------------
1       Rahul Sharma     84.2%
2       Priya Singh      76.5%
3       Amit Kumar       68.1%
4       Candidate 4      51.7%
```

## 9. Explainable Ranking 

The application explains why a candidate received their score.

Example:
```text
Matched 4 of 5 required skills.

Missing skills:
Machine Learning

Experience requirement met
(3 years).

Education requirement matched.
```
This makes the ranking easier to understand instead of providing only a numerical score.

# Installation

## 1. Clone the repository 

```text
git clone YOUR_GITHUB_REPOSITORY_URL
```
Move into the project directory:

## 2. Create a virtual environment

```text
python -m venv venv
```


## 3. Install dependencies


Run:
```text
python -m nltk.downloader punkt punkt_tab stopwords wordnet
```
If your version of NLTK requires additional resources, download them when prompted.

# Privacy and Security

Resume files can contain sensitive personal information.

For this project:
- Do not upload real candidate resumes containing unnecessary personal information to a public GitHub repository.
- Do not commit private resumes.
- Do not commit generated candidate reports containing personal information.
- Use sample or anonymized resumes for demonstrations.
Add sensitive files to .gitignore.

# Limitations

This project is a prototype and has several limitations.

### 1. Rule-Based Information Extraction
Candidate information is extracted using predefined patterns and keywords. Complex resume formats may not be parsed correctly.
### 2. Limited Skill Dictionary
The current system uses a predefined list of skills. New or uncommon technologies may not be detected.
### 3. Education Matching
Education matching is currently based on keyword matching and does not fully understand degree equivalence.
### 4. Experience Extraction
Experience extraction may not correctly interpret every possible resume format.
### 5. Scoring Weights
The current scoring weights are manually defined:
TF-IDF: 30%
Skills: 50%
Experience: 15%
Education: 5%
These values have not been statistically validated.
### 6. Limited Use of Semantic Models

Although Word2Vec and SBERT are implemented for model comparison, the current final ranking formula primarily uses TF-IDF similarity along with skill, experience, and education scores.

Future versions could investigate incorporating semantic similarity models into the final scoring system.
### 7. Human Review Required
The system should be used as a screening aid, not as an automatic final hiring decision-maker.
